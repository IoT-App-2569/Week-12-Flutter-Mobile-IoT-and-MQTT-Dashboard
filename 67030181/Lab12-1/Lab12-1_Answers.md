## สรุปสิ่งที่ทำในแล็บนี้
ในแล็บนี้ผมเริ่มต้นด้วยการเช็คเครื่องมือด้วยคำสั่ง `flutter doctor` ดูว่าตัว SDK พร้อมใช้งานไหม จากนั้นสร้างโปรเจกต์ชื่อ `iot_mqtt_basics` แล้วลงไลบรารี `mqtt_client` เพื่อใช้ต่อกับ Eclipse Mosquitto Broker ที่รันอยู่ในเครื่องคอมพิวเตอร์ผ่านพอร์ต 1883 

ตัวแอปในไฟล์ `lib/main.dart` จะมีช่องให้กรอก IP ของ Broker มีปุ่ม Connect, Disconnect และปุ่ม Publish สำหรับลองส่งข้อความ `test/flutter/ping` ไปที่โบรกเกอร์ แล้วหน้าจอก็จะคอย Subscribe หัวข้อ `test/broker/echo` เพื่อดักฟังข้อความตอบกลับจากเทอร์มินัลด้วยครับ

## ผลการทดลองที่เกิดขึ้นจริง
1. **ตอนเปิด Broker:** ผมรันคำสั่ง `mosquitto -c mosquitto.conf -v` ใน PowerShell ให้ Broker เริ่มทำงาน
2. **ตอนเปิดฟังข้อความจากคอม:** ใช้คำสั่ง `mosquitto_sub -h 127.0.0.1 -p 1883 -t "test/flutter/ping" -v` รอดักฟังไว้
3. **ตอนสั่งรันแอปบน Windows:** พอสั่ง `flutter run -d windows` หน้าต่างแอปเปิดขึ้นมา กรอก IP เป็น `127.0.0.1` แล้วกด Connect สถานะเปลี่ยนเป็นสีเขียวทันที และในช่อง Log ขึ้นว่า Subscribe หัวข้อเรียบร้อย
4. **ตอนกดส่งข้อความ:** พอกดปุ่ม "Publish Test Message (Ping)" บนแอป หน้าต่าง PowerShell ฝั่ง `mosquitto_sub` ก็ได้รับข้อความว่า `Hello from Flutter at ...` ทันที
5. **ตอนส่งจาก CLI กลับเข้าแอป:** ลองพิมพ์ `mosquitto_pub -h 127.0.0.1 -p 1883 -t "test/broker/echo" -m "Hello 67030281"` ในหน้าจอแอปตรงกล่อง Log ก็มีข้อความเด้งขึ้นมาจริง แสดงว่าการรับส่งข้อมูลสองทางทำงานได้สมบูรณ์ครับ

## คำตอบคำถามท้ายการทดลอง

### ข้อ 1: เพราะเหตุใดเราจึงต้องสุ่มชื่อ `clientId` เช่นการใส่ Timestamp ต่อท้าย แทนที่จะตั้งชื่อแบบคงที่?
**ตอบ:**  
เพราะว่ากฎของ MQTT Broker มันไม่อนุญาตให้มี Client ที่ใช้ชื่อ `clientId` ซ้ำกันเชื่อมต่อเข้ามาพร้อมกันครับ ถ้าเราตั้งชื่อฟิกซ์ตายตัวไว้ เช่นตั้งว่า `Flutter_Client` แล้วถ้าเราเปิดแอปซ้อนกันสองหน้าจอ หรือมีเพื่อนในห้องแล็บใช้ชื่อเดียวกันเป๊ะ ตัว Broker มันจะเข้าใจว่าเป็นการล็อกอินใหม่ แล้วมันจะไปสั่งเตะ (Disconnect) เครื่องเดิมหลุดออกทันที 

ทีนี้พอเครื่องเก่าหลุด ถ้าโค้ดเราเขียนระบบ Auto-Reconnect ไว้ เครื่องเก่ามันก็จะพยายามต่อกลับเข้ามาใหม่ แล้วก็ไปเตะเครื่องใหม่ออก สลับกันเตะไปเตะมาวนลูปไม่รู้จบ (เรียกว่าอาการ Ping-Pong หรือ Connection Thrashing) ทำให้เน็ตค้างและส่งข้อมูลไม่ได้เลย ดังนั้นการเอา Timestamp ที่เป็นเวลาเสี้ยววินาทีมาต่อท้ายชื่อ เช่น `Flutter_67030281_Lab12_1_${DateTime.now().millisecondsSinceEpoch}` จะทำให้ชื่อไม่ซ้ำกับใครแน่นอนครับ

### ข้อ 2: หากหน้าจอ Flutter รันบนอุปกรณ์จริง (Physical Android Phone) เหตุใดการกรอก IP `127.0.0.1` จึงไม่สามารถเชื่อมต่อ Broker ได้? และต้องใช้ IP ใด?
**ตอบ:**  
เพราะว่า `127.0.0.1` หรือที่เรียกกันว่า `localhost` มันหมายถึงตัวเครื่องของมันเองครับ พอเราเอาแอปไปรันบนมือถือจริง ตัวแอปมันก็จะวิ่งไปหา Broker ในระบบของเครื่องมือถือ ซึ่งในมือถือเราไม่ได้ลงโปรแกรม Mosquitto เอาไว้ มันก็เลยหาไม่เจอแล้วฟ้อง Error ตัดการเชื่อมต่อทันที

วิธีที่ถูกต้องคือ เราต้องให้มือถือกับคอมพิวเตอร์ต่อ Wi-Fi หรือ Hotspot วงเดียวกันก่อน จากนั้นมาที่คอมพิวเตอร์ เปิด PowerShell แล้วพิมพ์คำสั่ง `ipconfig` ดูตรงการ์ด Wi-Fi ว่าเครื่องคอมเราได้ IP เลขอะไร เช่น `192.168.1.105` แล้วเวลาจะต่อในมือถือ ให้เอาเลข IP นั้นมากรอกแทน และที่สำคัญคือไฟล์ `mosquitto.conf` บนคอมต้องเปิด `listener 1883 0.0.0.0` ไว้ด้วย เพื่อให้ Broker ยอมรับการเชื่อมต่อที่มาจากภายนอกเครื่องครับ

### ข้อ 3: การตั้งค่า `keepAlivePeriod` มีความจำเป็นอย่างไรในสภาพแวดล้อมเครือข่ายไร้สาย?
**ตอบ:**  
จำเป็นมากครับ เพราะเครือข่ายไร้สายอย่าง Wi-Fi หรือเน็ตมือถือ 4G/5G มันชอบมีปัญหาเรื่องสัญญาณขาดหายหรือเราเตอร์ตัดการเชื่อมต่อ โดยมีเหตุผลสำคัญ 3 เรื่องคือ:
1. **ป้องกันเราเตอร์ตัดเน็ต (NAT Timeout):** พวกเราเตอร์หรือเกตเวย์จะมีระบบเคลียร์ช่องสัญญาณ ถ้าไม่มีข้อมูลวิ่งผ่านเลยสักพัก (มักจะประมาณ 30-60 วินาที) มันจะตัดการเชื่อมต่อทิ้งไปเอง การตั้ง Keep Alive (ในโค้ดตั้งไว้ 20 วิ) จะทำให้แอปคอยส่งแพ็กเก็ตสั้นๆ (Ping) ไปสะกิด Broker เรื่อยๆ ทำให้ท่อการเชื่อมต่อเปิดค้างไว้ตลอด
2. **ตรวจจับเวลาเน็ตหลุดเงียบ:** ถ้าเราถือมือถือเดินออกนอกบ้านจนหลุดสัญญาณ Wi-Fi หรือมือถือแบตหมดดับไป เครื่องมันจะไม่ทันได้ส่งข้อความบอกลาไปหา Broker ทำให้ Broker ยังคิดว่าแอปออนไลน์อยู่ แต่ถ้ามี Keep Alive พ้นช่วงเวลาที่กำหนดแล้ว Broker ไม่ได้รับ Ping ตอบกลับ Broker จะรู้ทันทีว่าเครื่องหลุดไปแล้ว และจะช่วยส่งข้อความเตือน (LWT) ไปบอกคนอื่นให้
3. **ช่วยให้แอปรู้ตัวว่าเน็ตหลุด:** ตัวแอปเองถ้าส่ง Ping ไปแล้ว Broker ไม่ตอบกลับมา แอปก็จะรู้ตัวแล้วเริ่มทำการเชื่อมต่อใหม่ (Auto-Reconnect) ให้เองโดยที่ผู้ใช้ไม่ต้องกดปิดเปิดแอปใหม่ครับ

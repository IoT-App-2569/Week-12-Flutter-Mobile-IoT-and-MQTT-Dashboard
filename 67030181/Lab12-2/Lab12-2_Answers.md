**แล็บ:** 12.2 การสร้างสวิตช์ควบคุมอุปกรณ์สองทาง (Bi-directional Actuator Switch) พร้อมระบบ Feedback และสถานะ LWT

## สรุปสิ่งที่ทำในแล็บนี้
แล็บนี้ผมพัฒนาต่อจากแล็บแรก โดยสร้างหน้าจอควบคุมไฟสไตล์ Dark Mode และ Glassmorphism ในไฟล์ `lib/actuator_control_screen.dart` ซึ่งไม่ได้มีแค่ปุ่มเปิดปิดธรรมดา แต่ทำระบบ State Synchronization สองทางไว้ด้วย คือเวลาเราแตะสวิตช์ แอปจะส่งคำสั่งเป็น JSON เช่น `{"led": "ON"}` ไปที่หัวข้อ `iot/esp32/control` แล้วตัวแอปจะยังไม่เปลี่ยนสถานะทันที แต่จะขึ้นว่า "Waiting ACK..." เพื่อรอฟังข้อความยืนยันจากบอร์ดที่หัวข้อ `iot/esp32/led_ack` ก่อนว่าหลอดไฟติดจริงหรือยัง ถ้าติดจริงแล้วสวิตช์ถึงจะเปิดและไอคอนหลอดไฟจะเรืองแสงสีเขียว

นอกจากนี้ยังมีการคอยดักฟังหัวข้อ `iot/esp32/status` เพื่อดูว่าบอร์ด ESP32 ออนไลน์อยู่ไหม ถ้าบอร์ดหลุดหรือดับไป หน้าจอก็จะขึ้นแถบสีแดงเตือนว่าออฟไลน์ และล็อคไม่ให้เรากดสวิตช์ได้ครับ

---

## ผลการทดลองที่เกิดขึ้นจริง (ทดสอบด้วย Mosquitto CLI จำลอง)
1. **ทดสอบสถานะบอร์ดออนไลน์:** 
   ลองยิงคำสั่ง `mosquitto_pub -h 127.0.0.1 -p 1883 -t "iot/esp32/status" -m "online" -r` จำลองว่าบอร์ดต่อเน็ตสำเร็จ 
   *ผลที่เห็น:* ป้ายสถานะด้านบนของแอปเปลี่ยนจากสีเทาเป็นสีเขียวทันที เขียนว่า `ESP32 ฮาร์ดแวร์: ออนไลน์ (ONLINE)` และปลดล็อคให้กดสวิตช์ได้
2. **ทดสอบกดเปิดสวิตช์:** 
   ลองเปิดฟังคำสั่งไว้ด้วย `mosquitto_sub -h 127.0.0.1 -p 1883 -t "iot/esp32/control" -v` แล้วเอานิ้วแตะสวิตช์ในแอป 
   *ผลที่เห็น:* ตัวมือถือมีการสั่นเบาๆ (Haptic Feedback) และในหน้าต่าง PowerShell ได้รับข้อความ `{"led":"ON"}` ทันที ส่วนหน้าจอแอปขึ้นข้อความสีส้มว่ากำลังรอการยืนยันจากบอร์ด
3. **ทดสอบบอร์ดตอบกลับยืนยัน (ACK):** 
   ยิงคำสั่ง `mosquitto_pub -h 127.0.0.1 -p 1883 -t "iot/esp32/led_ack" -m '{"led_state": true, "ack": true}'`
   *ผลที่เห็น:* หน้าจอแอปเปลี่ยนสถานะสวิตช์เป็นเปิดทันที กรอบและไอคอนหลอดไฟติดเป็นแสงสีเขียวนีออนสวยงาม แสดงว่าระบบรับสัญญาณ ACK ได้ถูกต้อง
4. **ทดสอบสถานการณ์บอร์ดดับหรือเน็ตหลุด (LWT):** 
   ลองยิง `mosquitto_pub -h 127.0.0.1 -p 1883 -t "iot/esp32/status" -m "offline" -r`
   *ผลที่เห็น:* หน้าจอแอปเปลี่ยนเป็นแถบสีแดงทันทีว่า `ESP32 ฮาร์ดแวร์: ออฟไลน์ (OFFLINE)` และถ้าเราพยายามจะกดสวิตช์ จะมีแถบ SnackBar ด้านล่างเตือนว่าอุปกรณ์ออฟไลน์อยู่ กดไม่ได้ครับ

## คำตอบคำถามท้ายการทดลอง

### ข้อ 1: ประโยชน์ของการรอสัญญาณ ACK จากหัวข้อ `iot/esp32/led_ack` แทนการเปลี่ยน UI ทันที (Optimistic Update) คืออะไร?
**ตอบ:**  
ข้อดีหลักๆ เลยคือ **ป้องกันไม่ให้หน้าจอกับของจริงไม่ตรงกัน (UI Desynchronization)** ครับ 

ถ้าเราทำแบบ Optimistic Update พอกดปุ่มปุ๊บ สวิตช์ในจอก็เด้งไปเป็น "เปิด" ทันที ทั้งๆ ที่ในความเป็นจริง สายไฟอาจจะหลุด บอร์ดอาจจะแฮงก์ หรือไฟดับอยู่ ทำให้คนใช้เข้าใจผิดว่าเปิดเครื่องจักรหรือเปิดไฟสำเร็จแล้ว ทั้งที่ของจริงไม่ได้ติดเลย 

การรอสัญญาณ ACK จะการันตีว่า โค้ดในบอร์ด ESP32 มันสั่งให้ขา GPIO จ่ายไฟออกไปติดหลอดไฟจริงเรียบร้อยแล้ว แล้วค่อยส่งข้อความกลับมายืนยัน ทำให้สิ่งที่เห็นบนหน้าจอกับสถานะทางกายภาพของอุปกรณ์ตรงกัน 100% เสมอ และถ้าส่งไปแล้วบอร์ดไม่ตอบกลับมา ตัวแอปก็ยังสามารถเด้งสวิตช์กลับมาอยู่ที่เดิมเพื่อบอกให้เรารู้ว่าส่งคำสั่งไม่สำเร็จได้ด้วยครับ

### ข้อ 2: ทำไมเราจึงควรตั้งแฟล็ก Retain (`-r`) สำหรับหัวข้อสถานะ `iot/esp32/status`?
**ตอบ:**  
เพราะว่า MQTT ปกติมันทำงานแบบส่งแล้วจบเลย ถ้าตอนที่บอร์ดส่งคำว่า `"online"` ขึ้นมา แล้วตอนนั้นเรายังไม่ได้เปิดแอป พอเรามาเปิดแอปทีหลัง ตัวแอปก็จะไม่ได้รับข้อความนั้นเลย ทำให้หน้าจอค้างอยู่ที่สถานะไม่รู้เรื่อง หรือคิดว่าบอร์ดดับอยู่ ทั้งๆ ที่บอร์ดมันเปิดรออยู่ตั้งนานแล้ว

การใส่แฟล็ก Retain (`-r`) จะเป็นการบอกให้ตัว Mosquitto Broker ช่วยจำข้อความล่าสุดนั้นไว้ในเมมโมรี่ของมันตลอดเวลา พอเราเปิดแอปขึ้นมาเมื่อไหร่แล้วไปกด Subscribe ปุ๊บ ตัว Broker จะรีบปาข้อความล่าสุดที่มันจำไว้ส่งให้แอปเราทันที ทำให้หน้าจอเปิดปุ๊บก็รู้ปั๊บว่าบอร์ดออนไลน์อยู่ ไม่ต้องมารอให้บอร์ดส่งซ้ำ และพอเวลาบอร์ดเน็ตหลุดจริงๆ โบรกเกอร์ก็จะเอาข้อความ LWT ที่เป็น `"offline"` มาแปะทับแทน ทำให้คนที่เปิดแอปมาใหม่ก็เห็นสถานะจริงว่าบอร์ดออฟไลน์อยู่ทันทีครับ

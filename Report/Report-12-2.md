### 2. คำถามท้ายการทดลอง 12.2 (Review Questions)

**1. ประโยชน์ของการรอสัญญาณ ACK จากหัวข้อ `iot/esp32/led_ack` แทนการเปลี่ยน UI ทันที (Optimistic Update) คืออะไร?**

**ตอบ:** เพื่อให้หน้าจอแอปพลิเคชันแสดงผลตรงกับ "สถานะจริงทางกายภาพ" ของฮาร์ดแวร์ 100% หากเปลี่ยน UI ให้สว่างทันทีที่ผู้ใช้กด แต่เกิดปัญหาเครือข่ายหลุดกลางทางหรืออุปกรณ์พัง หน้าจอจะแสดงผลหลอกผู้ใช้ การรอ ACK ช่วยยืนยันความสำเร็จของคำสั่ง ป้องกันข้อผิดพลาด และทำให้ระบบ IoT มีความน่าเชื่อถือสูง

**2. ทำไมเราจึงควรตั้งแฟล็ก Retain (`-r`) สำหรับหัวข้อสถานะ `iot/esp32/status`?**

**ตอบ:** การใช้ Retain flag จะสั่งให้ Mosquitto Broker จดจำข้อความสถานะล่าสุด ของหัวข้อนี้เอาไว้เสมอ ทำให้เมื่อเปิดแอปพลิเคชันขึ้นมาใหม่ แอปจะได้รับข้อความสถานะล่าสุดทันทีที่เชื่อมต่อสำเร็จ โดยไม่ต้องรอให้ฮาร์ดแวร์ส่งสถานะมาใหม่อีกรอบ แอปจึงแสดงผล UI ได้ถูกต้องตั้งแต่เสี้ยววินาทีแรก

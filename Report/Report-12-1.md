## 4. ทดสอบส่งข้อความสองทาง

- บนหน้าจอ Flutter: กรอก IP เป็น **`127.0.0.1`** (หรือ IP ของ Broker ที่เปิดรับ) แล้วกดปุ่ม **Connect**

  ![alt text](/Report/img/image.png)

- เมื่อสถานะเปลี่ยนเป็นสีเขียว ให้กดปุ่ม **Publish Test Message**
- สังเกตหน้าต่าง PowerShell `mosquitto_sub` ว่าได้รับข้อความ Ping หรือไม่

  ![alt text](/Report/img/image-1.png)

- ในอีกหน้าต่าง PowerShell ส่งข้อความตอบกลับไปยังหัวข้อที่ Flutter รอฟัง:

  ```powershell
  mosquitto_pub -h 127.0.0.1 -p 1883 -t "test/broker/echo" -m "Echo response from CLI"
  ```

- ตรวจสอบว่าในช่อง Logs ของ Flutter App แสดงข้อความที่ได้รับอย่างถูกต้อง

## 4. คำถามท้ายการทดลอง (Review Questions)

1. เพราะเหตุใดเราจึงต้องสุ่มชื่อ `clientId` เช่นการใส่ Timestamp ต่อท้าย แทนที่จะตั้งชื่อแบบคงที่?

   **ตอบ** กฎของโปรโตคอล MQTT บังคับว่าอุปกรณ์ทุกตัวที่เชื่อมต่อเข้า Broker จะต้องมี clientId ที่ ห้ามซ้ำกันโดยเด็ดขาด หากมี Client ใหม่พยายามเชื่อมต่อด้วย ID ที่มีคนใช้อยู่ Broker จะตัดการเชื่อมต่อ เครื่องเก่าออกทันที การนำเวลา มาต่อท้ายจึงเป็นเทคนิคที่ช่วยการันตีว่า ID จะไม่ซ้ำกันแน่นอนในแต่ละครั้งที่เรารันแอป

2. หากหน้าจอ Flutter รันบนอุปกรณ์จริง (Physical Android Phone) เหตุใดการกรอก IP `127.0.0.1` จึงไม่สามารถเชื่อมต่อ Broker ได้? และต้องใช้ IP ใด?

   **ตอบ** 127.0.0.1 หมายถึง "ตัวอุปกรณ์นั้นๆ เอง" หากนำไปกรอกตัวแอปก็จะพยายามค้นหา Broker ภายในเครื่อง ทำให้หาไม่เจอ

   ต้องเปลี่ยนไปใช้ IPv4 Address ของเครื่องคอมพิวเตอร์ ที่รัน Broker อยู่

3. การตั้งค่า `keepAlivePeriod` มีความจำเป็นอย่างไรในสภาพแวดล้อมเครือข่ายไร้สาย?

   **ตอบ** เครือข่ายไร้สาย มักมีสัญญาณที่ไม่เสถียรและอาจหลุดได้เงียบๆ การตั้งค่า keepAlivePeriod จะทำให้อุปกรณ์คอยส่งแพ็กเก็ต PINGREQ ไปหา Broker เป็นระยะ กลไกนี้ช่วยให้ทั้งฝั่งแอปและ Broker รู้ว่าการเชื่อมต่อขาดหายไปแล้ว และสามารถสั่งให้ระบบเริ่มกระบวนการเชื่อมต่อใหม่ ได้ทันที

# ใบงานการทดลองที่ 12.3
## 4. สรุปผลและคำถามท้ายการทดลอง
1. เหตุใดการใช้ `TweenAnimationBuilder` จึงทำให้เข็มมาตรวัดดูนุ่มนวลและไม่กระตุก แม้ข้อมูลเซนเซอร์จะเข้ามาทุกๆ 500 มิลลิวินาที?

```text
**เพราะ `TweenAnimationBuilder` สร้างค่าระหว่างกลาง (Interpolation) จากค่าเดิมไปยังค่าใหม่ทีละเฟรม แทนการกระโดดไปยังค่าใหม่ทันที**
 
- ข้อมูลเข้ามาทุก 500 มิลลิวินาที หรือเพียง 2 ครั้งต่อวินาที หากวาดเฉพาะค่าที่ได้รับ เข็มจะกระโดดเป็นช่วงๆ คล้ายภาพเคลื่อนไหว 2 เฟรมต่อวินาที
- เมื่อค่า `end` ของ Tween เปลี่ยน `TweenAnimationBuilder` จะเริ่มแอนิเมชันจากค่าที่แสดงอยู่ปัจจุบันไปยังค่าใหม่ โดยคำนวณค่าระหว่างกลางทุกเฟรมของหน้าจอ (ประมาณ 60–120 เฟรมต่อวินาที) จึงเห็นเข็มเคลื่อนที่ต่อเนื่อง
- ระยะเวลาแอนิเมชัน 300 มิลลิวินาที สั้นกว่าช่วงห่างของข้อมูล (500 มิลลิวินาที) แอนิเมชันแต่ละรอบจึงจบก่อนข้อมูลถัดไปมาถึง เข็มไม่ค้างกลางทาง
- Curve `Curves.easeOutCubic` ทำให้เข็มเคลื่อนเร็วตอนเริ่มแล้วชะลอตอนใกล้ถึงค่าเป้าหมาย คล้ายความเฉื่อยของเข็มมาตรวัดจริง

```

2. การจำกัดความยาวของอาร์เรย์ `_history` ให้เก็บไม่เกิน 30 ตัวอย่าง ส่งผลดีต่อประสิทธิภาพหน่วยความจำของสมาร์ตโฟนอย่างไร?

```text
**ทำให้หน่วยความจำและภาระการวาดกราฟคงที่ ไม่เพิ่มขึ้นตามระยะเวลาที่เปิดแอป**
 
- หากไม่จำกัด ข้อมูลที่เข้ามา 2 ค่าต่อวินาทีจะสะสมเป็น 7,200 ค่าต่อชั่วโมง และกว่า 170,000 ค่าต่อวัน หน่วยความจำจะเพิ่มขึ้นเรื่อยๆ จนระบบปฏิบัติการอาจปิดแอปทิ้ง
- `_SparklinePainter` วนลูปวาดข้อมูลทุกตัวใน `_history` และ `shouldRepaint` คืนค่า `true` เสมอ ยิ่งข้อมูลมาก ยิ่งใช้ CPU มากในทุกครั้งที่วาด ทำให้หน้าจอกระตุกและเปลืองแบตเตอรี่
- การจำกัดไว้ที่ 30 ค่าด้วย `removeAt(0)` ทำให้ใช้หน่วยความจำเพียงหลักร้อยไบต์ และเวลาวาดคงที่ทุกรอบ
- กราฟยังอ่านง่าย เพราะระยะห่างแนวนอนระหว่างจุดคงที่ หากเก็บไว้หลายพันค่า เส้นจะอัดแน่นจนอ่านแนวโน้มไม่ออก
```

3. หากเซนเซอร์ส่งค่าผิดพลาด เช่น ค่านอกช่วง 0 - 3.3V หรือค่าเป็น `null` โค้ดส่วนใดใน `telemetry_dashboard_screen.dart` ที่ช่วยป้องกันไม่ให้แอปแครช?

```text
**มีการป้องกัน 3 ชั้น คือ บล็อก `try-catch` ตัวดำเนินการ Null-aware และการใช้ `clamp()` ตอนวาด**
 
- **`try-catch` ใน `_handleIncomingMessage`** ครอบ `jsonDecode()` และการแปลงชนิดข้อมูลไว้ หาก Payload ไม่ใช่ JSON ที่ถูกต้อง หรือค่าเป็นชนิดผิด เช่น `"voltage": "abc"` ข้อผิดพลาดจะถูกดักจับและพิมพ์ด้วย `debugPrint` แล้วข้ามข้อความนั้นไป แอปยังทำงานต่อได้
- **ตัวดำเนินการ Null-aware** `(data['voltage'] as num?)?.toDouble() ?? 0.0` รองรับกรณีค่าเป็น `null` หรือไม่มีฟิลด์นั้น โดยใช้ค่าเริ่มต้น `0.0` แทน ป้องกันข้อผิดพลาด Null Check
- **`clamp(0.0, 1.0)`** ใน `_GaugePainter` และ `_SparklinePainter` จำกัดอัตราส่วนของค่าไว้ในช่วง 0–1 ค่านอกช่วง เช่น `5.0 V` หรือ `-1.0 V` จึงไม่ทำให้เส้นโค้งเกิน 270 องศา หรือกราฟวาดหลุดออกนอกกรอบ
- `try-catch` ใน `_connect()` ยังป้องกันแอปแครชกรณีเชื่อมต่อ Broker ไม่สำเร็จ
```

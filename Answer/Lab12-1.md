## 6. คำถามท้ายการทดลอง

### ข้อ 1. ทำไมต้องสุ่มชื่อ `clientId` เช่นใส่ Timestamp ต่อท้าย แทนการตั้งชื่อคงที่?

ตามมาตรฐาน MQTT ใน Broker หนึ่งตัว **ห้ามมี Client ID ซ้ำกัน** ถ้ามี Client ใหม่ต่อเข้ามาด้วย ID เดิม Broker จะตัดการเชื่อมต่อของตัวเก่าทิ้งทันที (Session Takeover) ถ้าตั้งชื่อคงที่แล้วเปิดแอปหลายเครื่อง หรือรันแอปซ้ำขณะที่ Session เก่ายังค้างอยู่ จะเกิดการเตะกันไปมาและหลุดการเชื่อมต่อวนซ้ำ การต่อท้ายด้วย `DateTime.now().millisecondsSinceEpoch` ทำให้ทุกครั้งที่เชื่อมต่อได้ ID ไม่ซ้ำกัน

### ข้อ 2. ถ้ารันบนมือถือ Android จริง ทำไมใช้ IP `127.0.0.1` ไม่ได้? ต้องใช้ IP ใด?

`127.0.0.1` คือ **Loopback** ซึ่งหมายถึง “ตัวเครื่องนี้เอง” เมื่อแอปรันบนมือถือ IP นี้จึงชี้ไปที่ตัวมือถือ ไม่ใช่คอมพิวเตอร์ที่รัน Mosquitto ทำให้หา Broker ไม่เจอ

ต้องใช้ **IP วง LAN ของคอมพิวเตอร์ที่รัน Broker** (ดูได้จาก `ipconfig` เช่น `192.168.1.105`) โดยมือถือต้องอยู่ Wi-Fi วงเดียวกัน และ Broker ต้องรันด้วยไฟล์คอนฟิกที่มี `listener 1883 0.0.0.0` กับ `allow_anonymous true` (ไฟล์ `mosquitto.conf` ในโปรเจกต์) รวมทั้งเปิด Windows Firewall ให้พอร์ต 1883
(กรณีใช้ Android Emulator ให้ใช้ `10.0.2.2` ซึ่งชี้กลับไปที่คอมพิวเตอร์โฮสต์)

### ข้อ 3. `keepAlivePeriod` จำเป็นอย่างไรในเครือข่ายไร้สาย?

`keepAlivePeriod = 20` หมายความว่าถ้าไม่มีข้อมูลรับส่งเลยภายใน 20 วินาที Client จะส่ง **PINGREQ** ไปหา Broker แล้วรอ **PINGRESP** กลับมา ซึ่งมีประโยชน์ดังนี้

- **ตรวจจับการหลุดแบบเงียบ:** บน Wi-Fi หรือ 4G การเชื่อมต่อขาดได้โดยที่ TCP ไม่รู้ตัว เช่น เดินออกนอกระยะสัญญาณ ถ้าไม่มี Ping ทั้งสองฝั่งจะคิดว่ายังเชื่อมต่ออยู่
- **ให้ Broker ส่ง LWT ได้:** ถ้า Broker ไม่ได้รับอะไรจาก Client นานเกิน 1.5 เท่าของ Keep Alive จะถือว่า Client ตายและส่ง Last Will ออกไป
- **รักษา NAT/Router ไม่ให้ตัด Session ที่ไม่ได้ใช้งาน:** Router และเครือข่ายมือถือมักตัดการเชื่อมต่อ TCP ที่เงียบนานเกินไป

ถ้าตั้งค่าสั้นเกินไปจะเปลืองแบตและดาต้า ถ้ายาวเกินไปจะรู้ตัวช้าว่าหลุด ค่า 20–60 วินาทีจึงเหมาะกับมือถือ

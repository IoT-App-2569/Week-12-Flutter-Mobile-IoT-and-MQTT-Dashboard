## 4. คำถามท้ายการทดลอง (Review Questions)
1. เพราะเหตุใดเราจึงต้องสุ่มชื่อ `clientId` เช่นการใส่ Timestamp ต่อท้าย แทนที่จะตั้งชื่อแบบคงที่?
  คำตอบ: โปรโตคอล MQTT กำหนดให้ clientId ของอุปกรณ์ทุกตัวที่เชื่อมต่อมายัง Broker ต้องมีค่า ไม่ซ้ำกัน (Unique) หากมีอุปกรณ์มากกว่า 1 เครื่อง (หรือแอปพลิเคชันที่รันซ้ำ) ใช้ clientId ซ้ำกันเชื่อมต่อเข้ามา โบรกเกอร์จะสั่งตัดการเชื่อมต่อ (Disconnect) อุปกรณ์ตัวแรกออกทันที การเติม Timestamp ต่อท้ายจะช่วยสร้างค่าที่ไม่ซ้ำกันในทุกๆ ครั้งที่รันแอปพลิเคชัน

2. หากหน้าจอ Flutter รันบนอุปกรณ์จริง (Physical Android Phone) เหตุใดการกรอก IP `127.0.0.1` จึงไม่สามารถเชื่อมต่อ Broker ได้? และต้องใช้ IP ใด?
  IP 127.0.0.1 คือ Loopback Address หมายถึง "ตัวเครื่องปัจจุบันที่กำลังรันแอปอยู่" ดังนั้นเมื่อรันบนมือถือจริง 127.0.0.1 จะชี้ไปยังตัวมือถือเอง ไม่ใช่คอมพิวเตอร์ที่รัน Mosquitto Broker
  IP ที่ต้องใช้: ต้องใช้ IPv4 Address ของเครื่องคอมพิวเตอร์ ในวง LAN เดียวกัน (เช่น 192.168.1.XX ตรวจสอบได้โดยรัน ipconfig ใน PowerShell บนคอมพิวเตอร์)
  กำหนดค่าไฟล์คอนฟิก Mosquitto Broker ให้เปิดรับ IP ภายนอกด้วยคำสั่ง listener 1883 0.0.0.0 และ allow_anonymous true

3. การตั้งค่า `keepAlivePeriod` มีความจำเป็นอย่างไรในสภาพแวดล้อมเครือข่ายไร้สาย?
  คำตอบ: ช่วยตรวจสอบและรักษาความเสถียรของสถานะการเชื่อมต่อ (Heartbeat Connection) บนเครือข่ายไร้สายที่มีโอกาสสัญญาณหลุดชั่วคราว (Silent Disconnection):
  ตรวจจับสายหลุด: Client จะส่งแพ็กเกจ PINGREQ ไปหา Broker ทุกๆ ช่วงเวลาที่กำหนด (เช่น 20 วินาที) หากไม่ได้รับการตอบรับ ทั้งสองฝั่งจะรู้ทันทีว่าสายหลุดแล้วและสามารถเริ่มเชื่อมต่อใหม่ (Auto-Reconnect) ได้
  เปิดใช้งาน Last Will: ช่วยให้ Broker ส่งข้อความแจ้งสถานะอุปกรณ์หลุด (Last Will and Testament - LWT) ไปยัง Client อื่นๆ ในระบบได้อย่างถูกต้องทันทีเมื่อออฟไลน์

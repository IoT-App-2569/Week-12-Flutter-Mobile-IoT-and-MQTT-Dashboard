1. เพราะเหตุใดเราจึงต้องสุ่มชื่อ `clientId` เช่นการใส่ Timestamp ต่อท้าย แทนที่จะตั้งชื่อแบบคงที่?

```
เพราะ broker ใช้ clientId เป็นตัวระบุผู้เชื่อมต่อ และอนุญาตให้มีได้แค่ตัวเดียวต่อหนึ่งชื่อ ถ้าตั้งชื่อคงที่แล้วมี client อีกตัวใช้ชื่อเดียวกัน broker จะตัดการเชื่อมต่อตัวเก่าทิ้ง แล้วทั้งสองตัวจะเตะกันไปมาไม่หยุด การใส่ Timestamp ทำให้ชื่อไม่ซ้ำในแต่ละครั้งที่ต่อ
```

2. หากหน้าจอ Flutter รันบนอุปกรณ์จริง (Physical Android Phone) เหตุใดการกรอก IP `127.0.0.1` จึงไม่สามารถเชื่อมต่อ Broker ได้? และต้องใช้ IP ใด?

```
127.0.0.1 คือ loopback ที่ชี้กลับมาที่เครื่องตัวเองเสมอ ถ้าแอปรันบนมือถือ 127.0.0.1 จะหมายถึงตัวมือถือเอง ซึ่งไม่มี broker อยู่ ต้องใช้ IP ของคอมพิวเตอร์ที่รัน Mosquitto ในวง LAN เดียวกันกับมือถือ และ broker ต้องฟังที่ 0.0.0.0 พร้อมตั้ง allow_anonymous true ผ่านไฟล์คอนฟิก เพราะ Mosquitto 2. ขึ้นไปถ้ารันโดยไม่มีคอนฟิกจะฟังแค่ 127.0.0.1 ด้วย เเละต้องไม่มี firewall ปิดพอร์ต 1883
```

3. การตั้งค่า `keepAlivePeriod` มีความจำเป็นอย่างไรในสภาพแวดล้อมเครือข่ายไร้สาย?

```
keepAlive คือช่วงเวลาที่ client ต้องส่งอะไรมาให้ broker อย่างน้อยหนึ่งครั้ง ถ้าไม่มีข้อมูลก็ส่ง PINGREQ ให้ ใช้ตรวจว่าการเชื่อมต่อยังมีชีวิตอยู่หรือไม่ เพราะ Wi-Fi และมือถือหลุดได้เงียบๆ โดยที่ TCP ยังไม่รู้ตัว ถ้า broker ไม่ได้ยินอะไรเกินประมาณ 1.5 เท่าของค่านี้ จะถือว่า client ตายแล้วปิดการเชื่อมต่อและส่ง LWT ออก ฝั่ง client ก็ใช้ตรวจจับว่า broker หายเพื่อเชื่อมต่อใหม่ นอกจากนี้ยังช่วยให้ NAT ของเราเตอร์ไม่ลบการเชื่อมต่อที่เงียบเกินไป
```


```
เพราะ MQTT ส่งข้อความให้เฉพาะ client ที่ subscribe อยู่ตอนนั้น ถ้าบอร์ดส่ง online ไปก่อนที่แอปจะเปิด แอปที่เพิ่งเปิดหรือเพิ่งต่อใหม่จะไม่ได้รับข้อความนั้นและจะไม่รู้สถานะของบอร์ด (ค้างเป็น OFFLINE) เมื่อตั้ง retain ไว้ broker จะเก็บข้อความสถานะล่าสุดและส่งให้ทันทีที่ subscribe ใช้ได้ทั้งกับ online ตอนบอร์ดบูต และ offline ที่เป็น LWT ตอนบอร์ดหลุด แอปจึงเห็นสถานะจริงเสมอโดยไม่ต้องรอข้อความใหม่
```

## 4. สรุปผลและคำถามท้ายบทเรียน
1. เหตุใดการใช้ `IndexedStack` ใน `MainNavigationShell` จึงมีความสำคัญอย่างยิ่งสำหรับแอปพลิเคชัน IoT แบบ Multi-tab เมื่อเทียบกับการสลับวิดเจ็ตด้วย `body: _pages[_currentIndex]`?

```
IndexedStack เก็บทุกหน้าไว้ในสถานะ "ยังมีชีวิต" แล้วแค่ซ่อนหน้าที่ไม่ได้ดู หน้า Telemetry และหน้า Actuator จึงยังเชื่อมต่อ MQTT และรับข้อมูลอยู่เบื้องหลังตลอดแม้สลับแท็บ ส่วน body: _pages[_currentIndex] จะทำลายหน้าเดิมทิ้งทุกครั้งที่สลับ ซึ่งในแอปนี้ dispose() จะตัดการเชื่อมต่อ MQTT ด้วย พอสลับกลับต้องเชื่อมต่อใหม่ ค่าสูงสุด/ต่ำสุดและกราฟประวัติหายหมด และพลาดข้อความที่มาระหว่างนั้น เช่น ACK หรือสถานะ LWT ที่มาตอนอยู่อีกแท็บ แถมสิ้นเปลืองการเชื่อมต่อใหม่ทุกครั้ง
```

2. เมื่อเปรียบเทียบการพัฒนาด้วย Flutter ในสัปดาห์นี้ กับการเปิดหน้าเว็บ HTTP บนเบราว์เซอร์ในสัปดาห์ที่ 8-10 ข้อใดให้ประสบการณ์การใช้งาน (UX) และความเสถียรที่ดีกว่าเมื่อข้อมูลเซนเซอร์มาด้วยความถี่สูง? เพราะเหตุใด?

```
Flutter ที่ใช้ MQTT ให้ประสบการณ์และความเสถียรดีกว่าเมื่อข้อมูลมาถี่ เพราะ MQTT เปิดการเชื่อมต่อค้างไว้แล้ว broker ผลักข้อมูลมาให้ทันทีที่มี push ส่วนเว็บ HTTP ต้องให้เบราว์เซอร์ร้องขอซ้ำๆ ทุกครั้งมี header ขนาดใหญ่ มีความหน่วงจากการขอแล้วรอตอบ และข้อมูลที่เปลี่ยนระหว่างรอบหายไป ฝั่ง MQTT มี overhead ต่ำ มีระดับ QoS และ LWT บอกสถานะบอร์ดให้อัตโนมัติ นอกจากนี้ Flutter วาดมาตรวัดและกราฟเองด้วยกราฟิกเอนจินที่ 60 เฟรมต่อวินาที พร้อมแอนิเมชันนุ่มนวล ในขณะที่หน้าเว็บ HTTP ต้องโหลดหรือรีเฟรชหน้าใหม่ ภาพรวมจึงกระตุกและตอบสนองช้ากว่า
```

3. หากต้องการนำแอปพลิเคชันนี้ไปเผยแพร่จริงบน Google Play Store หรือ Apple App Store ขั้นตอนความปลอดภัยที่ต้องปรับปรุงเพิ่มเติมมีอะไรบ้าง? (พิจารณาเรื่อง MQTTS / TLS พอร์ต 8883, การเข้ารหัส Token ยืนยันตัวตน, และการเก็บรักษา Credential)

```
- เปลี่ยนจาก MQTT พอร์ต 1883 ที่ไม่เข้ารหัสเป็น MQTTS พอร์ต 8883 (TLS) และใช้ WSS สำหรับเวอร์ชันเว็บ พร้อมตรวจใบรับรองของ broker  เพื่อกัน man-in-the-middle ปิด allow_anonymous แล้วบังคับยืนยันตัวตนด้วย username/password หรือ mTLS
- ไม่ฝัง credential หรือกุญแจส่วนตัวไว้ในโค้ดหรือไฟล์ของแอป เพราะแกะออกจากแอปได้ ให้ผู้ใช้ล็อกอินแล้วรับ token อายุสั้น จากเซิร์ฟเวอร์แทน และเก็บ token ใน Keychain (iOS) หรือ Keystore (Android) ผ่านที่เก็บแบบเข้ารหัสอย่าง flutter_secure_storage ไม่เก็บเป็นข้อความธรรมดา
- จำกัดสิทธิ์ราย topic ด้วย ACL ใน broker ให้ผู้ใช้แต่ละคนเข้าถึงเฉพาะอุปกรณ์ของตัวเอง
- ใช้ชื่อโดเมนที่มีใบรับรองแทน IP ที่ฝังตายตัว และทำ obfuscation ของโค้ดตอน build จริง
```

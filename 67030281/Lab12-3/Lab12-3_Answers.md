## สรุปสิ่งที่ทำในแล็บนี้
ในแล็บนี้ผมสร้างหน้าจอแดชบอร์ดรับค่าข้อมูลแรงดันไฟฟ้าจากเซนเซอร์แบบเรียลไทม์ โดยหัวข้อที่ใช้คือ `iot/esp32/telemetry` ส่งข้อมูลมาเป็นรูปแบบ JSON เช่น `{"voltage": 2.50, "raw": 3102, "uptime": 10}` 

ตัวหน้าจอประกอบด้วย:
1. **เกจวัดทรงกลม (Radial Gauge):** ใช้ `CustomPainter` วาดเส้นโค้งไล่เฉดสีฟ้า เขียว เหลือง แดง และใช้ `TweenAnimationBuilder` มาช่วยทำให้เข็มมันหมุนตามค่าแรงดันอย่างนุ่มนวล ไม่กระตุก
2. **การ์ดสรุปตัวเลขสถิติ:** แสดงค่าดิบ ADC (0-4095), แรงดันสูงสุด (Max) และต่ำสุด (Min) ที่เคยตรวจวัดได้
3. **กราฟเส้นย้อนหลัง (Live Sparkline):** เก็บข้อมูลลงอาร์เรย์แบบเลื่อนไปเรื่อยๆ (Sliding Window) สูงสุด 30 จุด แล้ววาดเป็นเส้นกราฟเคลื่อนไหวตามเวลาจริง

นอกจากนี้ผมได้สร้างไฟล์ `pyTeleSim.py` ไว้ในโฟลเดอร์นี้ สำหรับรันจำลองส่งข้อมูลรูปคลื่นไซน์ (Sine Wave) ทุกๆ 0.5 วินาที เพื่อดูการขยับของเข็มและกราฟเส้นครับ

## ผลการทดลองที่เกิดขึ้นจริง
1. **ทดสอบรันตัวจำลอง Python (`python pyTeleSim.py`):**
   ในเทอร์มินัลสคริปต์เริ่มส่งค่าแรงดันที่คำนวณจากสูตรไซน์ เช่น `1.65V`, `2.10V`, `3.15V`, `0.15V` สลับกันไปเรื่อยๆ ทุก 500 มิลลิวินาที
2. **สังเกตหน้าจอ Flutter:**
   - เข็มและแถบสีบน Radial Gauge กวาดขึ้นลงตามรอบคลื่นไซน์อย่างต่อเนื่อง แอนิเมชันลื่นไหลเนียนตามาก ไม่มีการวาร์ปหรือกระตุกเป็นขั้นบันได
   - ช่องการ์ดสถิติ อัปเดตค่าดิบ ADC ตามแรงดัน และบันทึกค่า Max ไว้ที่ประมาณ `3.15 V` และ Min ไว้ที่ `0.15 V`
   - กราฟเส้น Sparkline ด้านล่าง ตอนแรกเส้นจะค่อยๆ ลากจากซ้ายไปขวา พอครบ 30 จุดแล้ว กราฟจะเลื่อนไปทางซ้ายเรื่อยๆ เหมือนกับคลื่นน้ำที่กำลังไหล สวยงามและไม่กินแรมเครื่องเลยครับ

## คำตอบคำถามท้ายการทดลอง

### ข้อ 1: เหตุใดการใช้ `TweenAnimationBuilder` จึงทำให้เข็มมาตรวัดดูนุ่มนวลและไม่กระตุก แม้ข้อมูลเซนเซอร์จะเข้ามาทุกๆ 500 มิลลิวินาที?
**ตอบ:**  
เพราะว่าข้อมูลจากเซนเซอร์มันเข้ามาทีละก้อนแบบเว้นช่วง (Discrete Step) ครับ เช่นตอนแรกส่งมา 1.0V แล้วอีกครึ่งวินาทีถัดมาส่งมา 2.8V ถ้าเราเอาค่าไปสั่งวาดตรงๆ เข็มมันจะกระโดดแวบไปเลย ทำให้ดูขัดตา 

แต่ตัว `TweenAnimationBuilder` มันจะเข้ามาช่วยคำนวณหาค่าระหว่างจุดเก่ากับจุดใหม่ (Interpolation) โดยซอยย่อยออกเป็นเฟรมเล็กๆ ตามความลื่นของหน้าจอมือถือ (เช่น 60 หรือ 120 เฟรมต่อวินาที) แล้วพอเราใส่ลูกเล่นเคิร์ฟ `Curves.easeOutCubic` เข้าไปด้วย เข็มมันจะเคลื่อนที่แบบมีแรงเฉื่อยเหมือนเข็มไมล์รถยนต์จริงๆ คือออกตัวเร็วแล้วค่อยๆ ผ่อนความเร็วลงก่อนจะหยุดตรงจุดหมาย และเราตั้งเวลาไว้ 300 ms ซึ่งน้อยกว่ารอบส่ง 500 ms ทำให้เข็มหมุนเข้าที่อย่างพอดีก่อนที่ค่ารอบใหม่จะส่งมาถึง เข็มก็เลยดูนุ่มนวลและไม่กระตุกเลยครับ

### ข้อ 2: การจำกัดความยาวของอาร์เรย์ `_history` ให้เก็บไม่เกิน 30 ตัวอย่าง ส่งผลดีต่อประสิทธิภาพหน่วยความจำของสมาร์ตโฟนอย่างไร?
**ตอบ:**  
ช่วยได้เยอะมากใน 2 เรื่องหลักๆ ครับ:
1. **ป้องกันไม่ให้แรมเต็มจนแอปเด้งดับ (Prevent OOM Crash):** เซนเซอร์ส่งข้อมูลมาวินาทีละ 2 ครั้ง ถ้าปล่อยให้แอปเก็บไปเรื่อยๆ ไม่จำกัด ชั่วโมงนึงก็ปาเข้าไป 7,200 ค่า วันนึงเป็นแสนค่า ตัวแปรอาร์เรย์จะบวมขึ้นเรื่อยๆ จนกินแรมมือถือจนหมด แล้วระบบ Android/iOS ก็จะสั่งปิดแอปเราทิ้ง การที่เราเช็คว่า `if (_history.length > 30) _history.removeAt(0);` จะทำให้เมมโมรี่ที่ใช้คงที่ตลอดเวลา ไม่บวมขึ้น
2. **ช่วยให้กราฟไม่หน่วง (GPU / Paint Optimization):** ทุกครั้งที่หน้าจอรีเฟรช ตัว `CustomPainter` จะต้องวนลูปคำนวณจุดพิกัดเพื่อลากเส้นกราฟ ถ้ามีข้อมูลเป็นหมื่นจุด มือถือจะต้องประมวลผลหนักมากจนเครื่องร้อนและจอกระตุก แต่พอเราล็อคไว้แค่ 30 จุดล่าสุด การวาดเส้นจะทำได้ไวมากในเสี้ยววินาที หน้าจอเลยรักษาความลื่นระดับ 60 FPS ได้สบายๆ ครับ

### ข้อ 3: หากเซนเซอร์ส่งค่าผิดพลาด เช่น ค่านอกช่วง 0 - 3.3V หรือค่าเป็น `null` โค้ดส่วนใดใน `telemetry_dashboard_screen.dart` ที่ช่วยป้องกันไม่ให้แอปแครช?
**ตอบ:**  
มีตัวช่วยกันเหนียวไว้ 3 จุดในโค้ดครับ:
1. **การใช้ตัว `??` (Null-Coalescing) ดักค่าว่าง:**
   ```dart
   final v = (data['voltage'] as num?)?.toDouble() ?? 0.0;
   final raw = (data['raw'] as num?)?.toInt() ?? 0;
   ```
   ถ้าเกิดว่าบอร์ดส่ง JSON มาแล้วไม่มีฟิลด์ `voltage` หรือส่งค่า `null` มา ตัวโค้ดจะไม่พัง แต่จะหยิบค่า `0.0` ที่เราใส่ไว้หลังเครื่องหมาย `??` ไปใช้งานแทนอัตโนมัติ ทำให้ไม่ติด Error ประเภท `Null is not a subtype of double`
2. **บล็อก `try-catch` ดักตอนแกะ JSON:**
   ถ้าบอร์ดส่งข้อความพังๆ มา เช่น ส่งข้อความธรรมดาที่ไม่ใช่ JSON หรือ JSON วงเล็บขาด ตัวคำสั่ง `jsonDecode()` จะโยน Error ออกมา แต่โค้ดเราครอบไว้ในบล็อก `try-catch` มันก็เลยแค่พิมพ์ฟ้องใน debug console แล้วปล่อยผ่านไป หน้าจอเลยไม่แครช
3. **การใช้ฟังก์ชัน `.clamp(0.0, 1.0)` ในตัววาดเกจและกราฟ:**
   เวลาเอาค่าไปคำนวณมุมองศาหรือพิกัดบนจอ เราจะครอบด้วย `.clamp(0.0, 1.0)` เสมอ ทำให้ต่อให้เซนเซอร์เพี้ยนส่งค่าติดลบ หรือค่าพุ่งไป 100V ตัวเลขสัดส่วนก็จะไม่เกินขอบเขต 0 ถึง 1 ทำให้เข็มไม่หมุนทะลุวงกลม และกราฟไม่ลากเส้นทะลุจอออกไปข้างนอกครับ
